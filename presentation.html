Frontend Lexing & Parsing

Construct a clean, object-oriented Abstract Syntax Tree (AST) hierarchy with resilient Semantic Scoping and 4-tier error handling.

  • Function-level symbol table management (NamedValues)
  • Rigorous arity checking, unknown variable tracking, and transactional IR rollback

Lower AST constructs into verified LLVM SSA Intermediate Representation and define cross-platform Target Architecture lowering for native machine code.

  • Direct SSA instruction generation via llvm::IRBuilder<>
  • Automated function integrity verification via llvm::verifyFunction
  • Target Machine Triple configuration and native object file (.o / .obj) emission pipeline

Frontend Stage 1

Lexical Analysis (Lexer Design)

lexer/lexer.cpp
🔍
Scanner Architecture

The lexer is implemented as a stateful character-by-character scanner in lexer.cpp driven by gettok().

  • Whitespace Filtration: Automatically skips spaces, tabs, and linebreaks via isspace().
  • Identifier & Keyword Buffer: Accumulates alphanumeric characters into IdentifierStr. Returns tok_def, tok_extern, or tok_identifier.
  • Numeric Literal Processing: Matches continuous digit sequences and decimal points into NumVal via strtod().
  • Comment Stripping: Scans from # to end-of-line and recursively requests next token.
  • Operator Passthrough: Returns unknown characters (e.g. +, *, () as their raw ASCII integer value [0–255].
// Token Enumeration in lexer/token.h
enum Token {
  tok_eof = -1,
  // Commands
  tok_def = -2,
  tok_extern = -3,
  // Primary Entities
  tok_identifier = -4,
  tok_number = -5
};

// Scanning Logic in lexer/lexer.cpp
if (isalpha(LastChar)) {
  IdentifierStr = LastChar;
  while (isalnum(LastChar = getchar()))
    IdentifierStr += LastChar;

  if (IdentifierStr == "def") return tok_def;
  if (IdentifierStr == "extern") return tok_extern;
  return tok_identifier;
}

Semantic Validation & Resilience

Semantic Analysis & Robust Error Handling

4-Tier Error Strategy
📋
Symbol Scoping & Type System
  • Function-Scoped Symbol Table: Managed via std::map<string, llvm::Value*> NamedValues. Cleared at the beginning of each function compilation and populated with bound formal arguments.
  • Unified Floating-Point Domain: All expressions resolve to 64-bit IEEE double (getDoubleTy).
  • Boolean Type Promotion: Comparison operations (<) evaluate to 1-bit integers and are zero-extended to floating-point via CreateUIToFP.
// Argument scope population in FunctionAST::codegen
NamedValues.clear();
for (auto &Arg : TheFunction->args()) {
  NamedValues[Arg.getName().data()] = &Arg;
}
🛡️
4-Tier Error Handling Architecture
  • Tier 1 — Syntax / Lexical Trapping: LogError() prints diagnostic messages to stderr and returns nullptr, allowing the REPL parser to skip faulty tokens without terminating.
  • Tier 2 — Scope Resolution Trapping: LogErrorV("Unknown variable name") catches undeclared identifiers in expressions and aborts the invalid branch.
  • Tier 3 — Signature & Arity Verification: Function invocations strictly compare argument counts against registered prototype definitions (CalleeF->arg_size() != Args.size()).
  • Tier 4 — Transactional Module Rollback: If codegen fails mid-body, the compiler executes TheFunction->eraseFromParent(), guaranteeing no corrupt partial IR pollutes the active module.

Backend Lowering

LLVM IR Code Generation Strategy

LLVM IRBuilder & SSA
⚙️
LLVM Core Infrastructure
  • LLVMContext (TheContext): Core environment owning type tables, constant pools, and memory arenas.
  • IRBuilder (Builder): High-level cursor that inserts instructions into basic blocks and performs constant folding.
  • Module (TheModule): Top-level container holding compiled functions, symbol tables, and external declarations.
  • SSA Form Guarantee: Generates instructions directly in Static Single Assignment form without mutable stack allocations.
// BinaryExprAST::codegen() in ast/BinaryExprAST.cpp
llvm::Value *BinaryExprAST::codegen() {
  llvm::Value *L = LHS->codegen();
  llvm::Value *R = RHS->codegen();
  if (!L || !R) return nullptr;

  switch (Op) {
    case '+': return Builder.CreateFAdd(L, R, "addtmp");
    case '-': return Builder.CreateFSub(L, R, "subtmp");
    case '*': return Builder.CreateFMul(L, R, "multmp");
    case '<':
      L = Builder.CreateFCmpULT(L, R, "cmptmp");
      return Builder.CreateUIToFP(L,
        llvm::Type::getDoubleTy(TheContext), "booltmp");
  }
}
