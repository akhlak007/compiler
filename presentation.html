Project Motivation & Objectives

Executive Summary
🎯
What is Kaleidoscope?

A procedural toy language designed to demonstrate complete compiler frontend architecture using the LLVM infrastructure.

  • All numerical data are 64-bit IEEE floating point (double)
  • First-class function definitions with def
  • C-style standard library binding with extern
  • Pure expression-based syntax
🏗️
Engineering Goals

Transition from language theory to practical, modular C++ implementation with LLVM toolchains:

  • High-speed tokenization without external tools (Flex/Lex)
  • Recursive Descent with Operator-Precedence parsing
  • Object-Oriented Abstract Syntax Tree (AST)
  • Direct translation to verified Static Single Assignment (SSA) LLVM IR
📦
Codebase Structure

Refactored into clean, single-responsibility C++ translation units:

  • lexer/: Token definitions and stream scanner
  • ast/: 7 modular polymorphic AST class definitions
  • parser/: Binary precedence & grammar engine
  • kaleidoscope/: LLVM Context, Module, and Builder
  • logger/: Error reporting and recovery

lexer/lexer.cpp
🔍
Scanner Architecture

The lexer is implemented as a stateful character-by-character scanner in lexer.cpp driven by gettok().

  • Whitespace Filtration: Automatically skips spaces, tabs, and linebreaks via isspace().
  • Identifier & Keyword Buffer: Accumulates alphanumeric characters into IdentifierStr. Returns tok_def, tok_extern, or tok_identifier.
  • Numeric Literal Processing: Matches continuous digit sequences and decimal points into NumVal via strtod().
  • Comment Stripping: Scans from # to end-of-line and recursively requests next token.
  • Operator Passthrough: Returns unknown characters (e.g. +, *, () as their raw ASCII integer value [0–255].
// Token Enumeration in lexer/token.h
enum Token {
  tok_eof = -1,
  // Commands
  tok_def = -2,
  tok_extern = -3,
  // Primary Entities
  tok_identifier = -4,
  tok_number = -5
};

// Scanning Logic in lexer/lexer.cpp
if (isalpha(LastChar)) {
  IdentifierStr = LastChar;
  while (isalnum(LastChar = getchar()))
    IdentifierStr += LastChar;

  if (IdentifierStr == "def") return tok_def;
  if (IdentifierStr == "extern") return tok_extern;
  return tok_identifier;
}

Parser Architecture & Operator Precedence

parser/parser.cpp
🌳
Operator Precedence Parsing

Kaleidoscope utilizes a hybrid Recursive Descent Parser for grammar rules combined with an Operator-Precedence Climbing algorithm for mathematical binary expressions.

Precedence Hierarchy Table
< : Priority 10 +, - : Priority 20 * : Priority 40
  • ParsePrimary() routes tokens to numbers, parenthesized expressions, or variables/function calls.
  • ParseBinOpRHS() dynamically groups subtrees based on comparative token precedence.
📊
Parsing: a + b * c Expression Tree

Operator precedence ensures * binds tighter to b and c, forming the subtree before attaching to +.

Symbol Table & Type Strategy
📋
Symbol Table Management

Managed globally via NamedValues map:

std::map<string, llvm::Value*>
NamedValues;
  • Scoped per function definition
  • Cleared upon each new function body compilation
  • Populated with named function formal parameters
🎯
Type Checking & Domain

Kaleidoscope enforces a unified floating-point model:

  • All numerical expressions resolve to Type::getDoubleTy(TheContext).
  • Boolean comparisons (<) evaluate to 1-bit int and are immediately cast to double via CreateUIToFP.
  • Arity verification: Function call argument count is strictly verified against prototype signature.
🛡️
Error Recovery Strategy

Robust logging prevents compiler crashes:

  • LogError: Emits syntax errors to stderr and returns nullptr.
  • LogErrorV: Catches unknown variables or incorrect argument counts during codegen.
  • If codegen fails, TheFunction->eraseFromParent() rolls back partial LLVM IR to maintain module integrity.

Backend Lowering

LLVM IR Code Generation Strategy

LLVM IRBuilder & SSA
⚙️
LLVM Core Infrastructure
  • LLVMContext (TheContext): Core environment owning type tables, constant pools, and memory arenas.
  • IRBuilder (Builder): High-level cursor that inserts instructions into basic blocks and performs constant folding.
  • Module (TheModule): Top-level container holding compiled functions, symbol tables, and external declarations.
  • SSA Form Guarantee: Generates instructions directly in Static Single Assignment form without mutable stack allocations.
// BinaryExprAST::codegen() in ast/BinaryExprAST.cpp
llvm::Value *BinaryExprAST::codegen() {
  llvm::Value *L = LHS->codegen();
  llvm::Value *R = RHS->codegen();
  if (!L || !R) return nullptr;

  switch (Op) {
    case '+': return Builder.CreateFAdd(L, R, "addtmp");
    case '-': return Builder.CreateFSub(L, R, "subtmp");
    case '*': return Builder.CreateFMul(L, R, "multmp");
    case '<':
      L = Builder.CreateFCmpULT(L, R, "cmptmp");
      return Builder.CreateUIToFP(L,
        llvm::Type::getDoubleTy(TheContext), "booltmp");
  }
}
