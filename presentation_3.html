Lexical Scanner Architecture & Complete Token Rules

Design Phase
Hand-Written Scanner (lexer/lexer.cpp)
  • Zero-Dependency Design: High-efficiency hand-written character stream tokenizer bypassing regex engine overhead.
  • Whitespace & Comments: Strips leading whitespace and discards single-line comments initiated by # until newline.

  • Numeric Literal Parsing: Consumes numeric strings and converts them via strtod into double-precision IEEE-754 values.

Parser Architecture & Operator-Precedence Climbing

Design Phase
Precedence Climbing Algorithm
  • Recursive Descent Core: Parses primary expressions (numbers, variables, parenthesis groups) recursively.
  • Dynamic Climbing: Compares the incoming operator's precedence with the current expression's minimum threshold.
  • Associativity Resolution: Correctly folds subtrees to the left when precedence matches, binding tighter operations deeper.
  • Complexity: Operates in strict O(N) linear time across arithmetic token sequences without backtracking.
OperatorPrecedence LevelAssociativity
<10 (Lowest)Left-to-Right
+ , -20 (Intermediate)Left-to-Right
*40 (Highest)Left-to-Right
Climbing Implementation (parser/parser.cpp)
std::unique_ptr<ExprAST> ParseBinOpRHS(int ExprPrec, std::unique_ptr<ExprAST> LHS) {
  while (true) {
    int TokPrec = GetTokPrecedence();
    if (TokPrec < ExprPrec) return LHS;

    int BinOp = CurTok;
    getNextToken(); // Eat operator

    auto RHS = ParsePrimary();
    if (!RHS) return nullptr;

    int NextPrec = GetTokPrecedence();
    if (TokPrec < NextPrec) {
      RHS = ParseBinOpRHS(TokPrec + 1, std::move(RHS));
      if (!RHS) return nullptr;
    }
    LHS = std::make_unique<BinaryExprAST>(BinOp, std::move(LHS), std::move(RHS));
  }
}

Polymorphic Abstract Syntax Tree (AST) Hierarchy

Design Phase
Base Interface: ExprAST

Root polymorphic base class defining pure virtual code emission:

class ExprAST {
public:
  virtual ~ExprAST() = default;
  virtual llvm::Value* codegen() = 0;
};

Managed via std::unique_ptr<ExprAST> ensuring zero memory leaks through RAII.

Expression Nodes
  • NumberExprAST: Holds literal double Val. Generates llvm::ConstantFP.
  • VariableExprAST: Holds variable std::string Name. Looks up value in NamedValues.
  • BinaryExprAST: Holds char Op, unique_ptr LHS, and unique_ptr RHS. Emits arithmetic instructions.
  • CallExprAST: Holds callee function name and vector<unique_ptr<ExprAST>> Args.
Function & Prototype Nodes
  • PrototypeAST: Encapsulates function signature: Name and parameter list vector<string> Args. Emits llvm::FunctionType.
  • FunctionAST: Captures complete definition: owns unique_ptr<PrototypeAST> Proto and unique_ptr<ExprAST> Body.
  • Top-Level Expression: Wrapped into an anonymous nullary function __anon_expr() for direct evaluation.

Criterion 2 • Semantic Analysis

Scoped Symbol Table Management & Variable Resolution

Semantic Analysis
Symbol Scoping Mechanics
  • NamedValues Symbol Table: Central repository implemented as std::map<std::string, llvm::Value*> storing in-scope variable registers.
  • Scope Lifecycle:
    • Upon entering function codegen, NamedValues.clear() resets the local scope.
    • Iterates over TheFunction->args(), recording parameter names and mapping them to their LLVM argument virtual registers.
    • During body traversal, VariableExprAST::codegen() verifies identifier visibility.
  • Unbound Identifier Detection: If an identifier lookup fails in NamedValues, a diagnostic error is emitted, and generation aborts safely.
Variable Lookup Implementation
llvm::Value* VariableExprAST::codegen() {
  // Look this variable up in the local symbol table.
  llvm::Value* V = NamedValues[Name];
  if (!V)
    return LogErrorV(("Unknown variable name: " + Name).c_str());

  return V;
}
Semantic Invariant:

No variable expression may lower to LLVM IR without an active binding in the current function activation frame.

Prototype Verification, Arity Integrity & LLVM Validation

Semantic Analysis
Arity & Signature Checks
  • Argument Count Matching: When invoking CallExprAST, the parser checks Args.size() == CalleeF->arg_size().
  • Mismatch Prevention: Calling foo(1, 2) when defined as def foo(x, y, z) immediately aborts with: "Incorrect # arguments passed".
  • Redefinition Guard: Verifies that subsequent definitions do not change argument counts for an existing prototype.
Duplicate Parameter Guards
  • Formal Parameter Uniqueness: Prototype declarations verify that argument identifiers are unique (e.g. def bar(x, x) is rejected).
  • Shadowing Protection: Argument names bind strictly to distinct formal parameter slots in TheFunction->args().
  • Symbol Cleanliness: Symbol mappings are isolated per-function, preventing cross-function state contamination.
llvm::verifyFunction Pass
  • SSA Form Validation: Automatically executes llvm::verifyFunction(*TheFunction) on all compiled units.
  • Integrity Enforcement: Validates basic block terminators, control flow graph edges, and phi node predecessors.
  • Transactional Rollback: If verification fails, the function is excised via TheFunction->eraseFromParent().

Criterion 3 • IR Strategy Implementation

LLVM SSA Lowering & IRBuilder Infrastructure

IR Strategy
Static Single Assignment (SSA) Principles
  • Infinite Virtual Register File: LLVM IR assigns values to virtual registers (%1, %2, %addtmp) that are immutable once written.
  • Direct AST Lowering: Employs llvm::IRBuilder<> positioned at basic block insertion points to emit SSA instructions on the fly.
  • Explicit Control Flow: Functions allocate an initial entry BasicBlock; control flow constructs synthesize divergent and convergent basic blocks.
  • Type Homogeneity: Kaleidoscope uses double-precision floating point (Type::getDoubleTy(TheContext)) across all expressions.
Function Codegen Pipeline (ast/FunctionAST.cpp)
llvm::Function* FunctionAST::codegen() {
  llvm::Function* TheFunction = TheModule->getFunction(Proto->getName());
  if (!TheFunction) TheFunction = Proto->codegen();
  if (!TheFunction) return nullptr;

  llvm::BasicBlock* BB = llvm::BasicBlock::Create(TheContext, "entry", TheFunction);
  Builder.SetInsertPoint(BB);

  NamedValues.clear();
  for (auto &Arg : TheFunction->args())
    NamedValues[std::string(Arg.getName())] = &Arg;

  if (llvm::Value* RetVal = Body->codegen()) {
    Builder.CreateRet(RetVal);
    llvm::verifyFunction(*TheFunction);
    return TheFunction;
  }
  TheFunction->eraseFromParent();
  return nullptr;
}

Criterion 4 • Executable Generation

Target Architecture, Memory Segments & Output Channels

Executable Generation
Target Memory Segments
  • Text Segment (.text): Houses compiled machine instructions for user routines (e.g. @average, @fib). Read-only and executable.
  • Data Segment (.rodata / .data): Stores numeric floating-point constants, string literals, and global module definitions.
  • Stack Frames: Function activation records holding incoming parameters (%a, %b) and temporary register spills.
  • Heap Segment: Available for dynamic data allocations via foreign C library calls (malloc).
Strict Output Channel Segregation
  • Standard Output (stdout):

    Dedicated strictly to interactive user interactions: REPL prompts (ready>), parsed construct notifications, and calculated function evaluation results.

  • Standard Error (stderr):

    Dedicated strictly to compiler diagnostics: syntax error messages, semantic warnings, LLVM module IR dumps, and Quadruple traces.

  • Channel Cleanliness: Prevents IR metadata from polluting user application pipelines, enabling clean piping to files or downstream tools.

4-Tier Error Handling & Resilient Syntax Recovery

Testing Phase
Tier 1: Lexical
  • Handles unknown control characters and illegal bytes.
  • Prevents lexer infinite loops on malformed numeric sequences.
  • Recovers by advancing character stream to next delimiter.
Tier 2: Syntactic
  • Catches unbalanced parenthesis groups (1 + 2.
  • Flags dangling operators (e.g. 4 + * 3).
  • Reports malformed prototype argument lists.
  • Discards malformed line and resets REPL prompt.
Tier 3: Semantic
  • Intercepts unbound variable lookups in NamedValues.
  • Prevents function calls with argument count mismatches.
  • Flags prototype redefinition inconsistencies.
  • Emits clear diagnostic messages to stderr.
Tier 4: Codegen/IR
  • Enforces SSA invariants via llvm::verifyFunction.
  • Detects malformed basic blocks or missing returns.
  • Transactional rollback: deletes corrupted functions via eraseFromParent().

🏁 Conclusion & Defense

Presentation 3: Summary & Discussion

Architectural Strengths
  • Decoupled modular design across frontend and backend.
  • Clean O(N) operator-precedence climbing parser.
  • Memory safety via polymorphic C++14 smart pointers.
  • Strict Quadruple IR mapping to industrial LLVM SSA.
Recognized Weaknesses & Roadmap
  • Restricted to 64-bit float primitives without integer typing.
  • Absence of aggregate heap allocations (arrays, structs).
  • Flat symbol table lacking lexical block shadowing.
  • Roadmap: Multi-type inference, mem2reg mutable variables.
